Preguntas sobre HTTP

Ejercicio 1 - Programación en Ambientes de Redes

  • 1) ¿Sobre qué protocolo binario está montado el protocolo HTTP?

    HTTP en sus versiones 1.x no está montado sobre un protocolo binario, sino sobre TCP, que es un protocolo de transporte. HTTP/2 sí es binario, y HTTP/3 está montado sobre QUIC, que a su vez usa UDP.

  • 2) ¿Cuáles son los clientes HTTP y los servidores HTTP más utilizados?

    Como clientes: los navegadores, CURL y las librerías nativas de los distintos lenguajes de desarrollo. Como servidores: los web servers en general, siendo Apache el ejemplo más común.

  • 3) ¿Qué verbos admite un comando en el requerimiento HTTP?

    GET para lectura, PUT para crear recursos, DELETE para borrarlos y POST para actualizarlos. También existen otros como HEAD y OPTIONS.

  • 4) ¿Qué contenido lleva el body de un requerimiento HTTP?

    Puede llevar datos en cualquier formato: los campos cargados en un formulario, archivos enviados en un proceso de upload, texto plano, JSON, XML o contenido binario.

  • 5) ¿Qué diferencia existe entre un URL y un URI?

    Un URI es un identificador genérico de un recurso. Un URL es un tipo de URI que además indica cómo localizarlo, por ejemplo http://dominio/recurso. En la práctica se usa el término URI para la parte que va después del host y el puerto, como /index.html o /clientes.

  • 6) ¿Cómo se almacena información relacionada con las respuestas HTTP?

    Principalmente a través de los headers, como Set-Cookie, Cache-Control y ETag. También mediante cookies, que el servidor manda con Set-Cookie y el navegador guarda para reenviarlas, en el body de la respuesta y en la caché del navegador.

  • 7) ¿Qué significa HTTP sobre conexiones preexistentes?

    Significa reutilizar una misma conexión TCP para múltiples transacciones HTTP, lo que en HTTP 1.1 se llama conexiones persistentes. El header Connection: Keep-Alive es el que pide mantener la conexión abierta mientras sea posible.

  • 8) ¿Qué significa Virtual Hosting?

    Es la capacidad de un servidor web de atender múltiples dominios sobre una única IP. Para eso se usa el header Host del requerimiento, que le indica al servidor a qué dominio se le está pidiendo el recurso. Se puede simular localmente con el archivo hosts de Windows.

  • 9) ¿Qué significa Cache por ETag?

    Es un mecanismo de caché que usa un identificador único, o fingerprint, asociado a cada recurso del servidor. El cliente manda ese ETag en el header If-None-Match y, si el recurso no cambió, el servidor responde Not Modified y el navegador carga desde su caché. Es más confiable que usar fechas porque no depende de la configuración horaria.

  • 10) ¿Por qué el HTTP se considera STATELESS?

    Porque cada requerimiento es independiente y el servidor no guarda estado entre una petición y la siguiente. Al cerrarse la conexión, cualquier aplicación pierde el estado, por lo que hay que recuperarlo por otros medios como cookies o sesiones.

  • 11) ¿Qué nueva versión de HTTP se está usando para mejorar la velocidad de la WEB?

    HTTP/2, desde 2015, que mejora la velocidad con multiplexación y compresión de cabeceras. Y HTTP/3, desde 2019, que mejora todavía más la velocidad de establecimiento de conexión usando QUIC sobre UDP.

  • 12) ¿Cómo va a mejorar el comportamiento de una aplicación WEB en ambientes ruidosos o de débil conexión?

    Con HTTP/3 sobre QUIC, que permite reconectar de inmediato ante una caída y funciona mejor en zonas con mucho ruido, exceso de tráfico o baja cobertura, como industrias, aeropuertos o lugares alejados de las ciudades. QUIC arma conexiones UDP más cortas y eficientes, y transporta mensajes multiplexados de manera independiente, lo que reduce el bloqueo cuando se pierde un paquete.
